Checking GitHub Releases…

Current release builds are unsigned technical-evaluator builds. macOS Gatekeeper or Windows SmartScreen may warn or block them. Do not disable operating-system security globally. Verify the SHA-256 file, inspect the source if needed, and wait for signed distribution if you are not comfortable evaluating an unsigned build.

Option A

Packaged GitHub Release, when available.

  1. Use the platform-aware button above only after it confirms a matching asset.
  2. Open the Release page and read its notes, supported architecture, and known issues.
  3. Download the matching asset and SHA256SUMS.txt.
  4. Verify the checksum before opening the archive.
  5. Keep a backup and begin with a small test folder.

If no release or compatible asset can be verified, use the source option below. A successful CI artifact is not the same as a durable GitHub Release.

Verify the download

Compare SHA-256 before running it.

From the folder containing the asset and checksum file:

# macOS or Linux
shasum -a 256 FileOrganiser-*

# Windows PowerShell
Get-FileHash .\FileOrganiser-* -Algorithm SHA256

Compare the complete hash with the matching line in SHA256SUMS.txt. A match confirms transfer integrity, not code signing or safety.

Option B

Run the source preview with Python 3.9+.

git clone https://github.com/Sebby1770/file-organiser.git
cd file-organiser
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -e .
python3 -m file_organiser

On Windows PowerShell, activate with .\.venv\Scripts\Activate.ps1, then use python in place of python3. Installing from a checkout avoids confusion with the unrelated US-spelled package name on PyPI.

Do not run pip install file-organizer. That US-spelled PyPI name belongs to another project. The exact file-organiser distribution name is not reserved until this project publishes it.

Build it yourself

Create a local PyInstaller build.

python3 -m pip install pyinstaller
python3 scripts/build_app.py

The output is still unsigned unless you configure platform signing yourself. See SIGNING.md for the release-readiness checklist.

Compatibility

What is and is not established.

  • The Python source targets Python 3.9 through 3.12.
  • The release workflow builds on the current GitHub-hosted macOS, Windows, and Ubuntu runners.
  • A runner build does not prove every OS version, CPU architecture, desktop environment, or permission setup.
  • macOS runner architecture and universal-binary status must be stated on each Release; do not assume Intel and Apple silicon are both supported.
  • Trusted installation requires real signing/notarisation setup, which is documented but not included as a repository secret.
